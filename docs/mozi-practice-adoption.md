# 墨知产品实践迁移到墨牍

2026-11-18 重新审视。源项目为本机 `markdown-press` 工作区，基线 `2f6b314`，更新、设置与生命周期相关文件含未提交改动。本次只读参考，没有修改墨知。源码存在、墨牍已实现、自动检查通过、原生操作通过是不同证据。

主要责任在执行：原 productize-app 0.8 已覆盖最终保存、损坏数据保护、迟到结果、首次绘制与错误反馈，此前只落实了部分主路径。skill 的缺口是缺少从原型转入桌面、从本地试用转入分发时重新评估适用性的入口，不能据此把已有要求说成新增经验。

## 原来已有要求，但落实不足

| 行为契约 | 原 skill 的依据 | 发现的缺口与本次实现 | 验证 |
| --- | --- | --- | --- |

| 冷启动外观一致 | design 的主题语义与首次绘制 | 原加载页固定深色。先读取必要主题，创建窗口时注入启动值，原生 chrome / 加载页 / 主界面统一；不把默认主题写回失败库 | 编译和配置检查通过；原生纸白/金属灰冷启动待验 |

## 本次明确不照搬的范围

- 编辑器多窗保存屏障、文件观察、Markdown 光标协议与知识库发布不适用于当前单窗口 RSS 阅读任务。
- 墨知的 beta-first 是源项目发布约定。墨牍当前只承诺正式渠道，保留验收门禁，不增加没有需求的多渠道索引。
- 墨知专用 macOS 安装脚本、固定安装路径与隔离属性处理不移入；使用 Tauri 标准更新器，不绕过平台保护。
- 字体文件导入、全文提取、分组管理、云同步、AI、远程图片和后台轮询没有纳入本次。字体枚举因用户已有自定义字体需求且缺少发现入口而补齐。

Mac 解锁后实际验证了 ⌘,、系统字体枚举、旧库迁移、0.1.0 验收客户端安装并重启到正式 0.1.1，以及正式客户端从 GitHub 检查更新。其余原生交互的覆盖边界见 [验收记录](../VALIDATION.md)。

## 全局设置

参考墨知的 `SettingsModal.tsx`、`InterfaceTab.tsx`、`EditorTab.tsx`、`ShortcutsTab.tsx` 和 `UpdatesTab.tsx`。此前把 ⌘, 指向局部外观，其他选项散落在阅读库菜单。现在通过左下角齿轮或 macOS 应用菜单「设置…」打开统一面板。Aa 保留原有就地调节，更新提示直达「关于与更新」。

| 来源能力 | 墨牍的选择 |
| --- | --- |
| 外观、主题色、系统主题、界面字号 | 集中在「外观」。纸质白与金属灰支持手动和跟随系统，正文和界面分别调整字号 |
| 预览字体、代码字体、可读行宽 | 使用正文和等宽字体各自的回退，窄行宽作用于正文。阅读控制补充打开文章时自动标为已读的开关 |
| 快捷键列表与配置 | 提供实际生效的按键列表以及阅读单键快捷键开关。快捷键数量少，暂未引入录入和冲突配置 |
| 版本、更新管理 | 保留正式渠道、自动检查、手动检查、跳过和恢复提示。下载状态由应用持有，切换设置分组不会中断任务 |
| 数据与业务设置 | 集中现有 JSON 备份与恢复、OPML 导出、归档恢复及存储位置。语言切换依赖完整本地化，测试渠道依赖真实分发渠道。笔记、发布、图床、索引、任务和 AI 依赖墨知自己的工作流 |
